# ADR-002: A trigger or a bigger server would not have fixed the overselling

- **Status:** Accepted
- **Date:** 2026-11-27
- **Decision owner:** Yaa Antwi

## Context

Nana was told that "triggers" might fix the overselling, and someone priced a bigger server for the slow report. The brief asks whether triggers alone would have solved overselling.

## Decision

Do not rely on either. A trigger is an automatic reaction that runs when a record changes. It is good for keeping records, but it cannot make two buyers take turns. The fix is the reservation in ADR-001. A trigger can still help with record keeping, which ADR-003 covers.

## Alternatives considered

### Alternative A: A trigger that checks stock

- **How it would work:** Every time stock changes, the database runs a check automatically.
- **Why it is attractive:** It cannot be forgotten.
- **Why rejected:** Two buyers at the same moment each trigger their own check, and each still sees one unit left. Both pass. This comes from the course reasoning (chapter 15.1). I did not build and test a trigger-only fix, so I am not claiming a test result for it.

### Alternative B: A bigger server

- **How it would work:** More power for the same design.
- **Why it is attractive:** No design work.
- **Why rejected:** The overselling comes from two orders landing at the same moment, not from the server being slow. For the report, the delay came from how the report was written (ADR-004), not from the size of the server.

## Consequences

- **What this buys:** Nana's money goes to the real fix, and he does not buy hardware that would not help.
- **What this costs:** Nothing extra.
- **What it costs the client if I am wrong:** A trigger-only build would oversell in a rush, the same way it did before.
- **What would make me revisit this:** Nothing for overselling. The trigger idea returns only for record keeping. **Who decides:** Nobody needs to. Nana only if he wants to revisit hardware.

## What this survives

This is a decision about what does not work. The build that replaces it survived the 400-buyer test (ADR-001).
